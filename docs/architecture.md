# Architecture - HK CoolPath AI

> **Hong Kong's heat problem should not only be measured. It should be
> navigated — and prevented.**

HK CoolPath AI is a spatial-AI demo platform with two audiences:

- **Citizens / tourists** — find cooler walking routes through Hong Kong.
- **Planners / policymakers** — evaluate heat *before* districts are built
  (design → simulate → compare → improve), demonstrated on a CONCEPTUAL
  Northern Metropolis scenario.

Everything runs locally with one command; all data providers sit behind
interfaces so real integrations (LandsD, HKO feeds, City Brain) replace mocks
without touching engines or UI.

```
Mobile (Expo + MapLibre RN)         React Native + expo-router
        │  fetch JSON only
        ▼
FastAPI (backend/app/main.py)       HTTP contract = schemas.py ⇄ mobile types.ts
        │
        ├── HeatMapService          time-dependent heat layer + explainability
        ├── PlannerService          interventions → before/after simulation
        │        │
        ▼        ▼
HeatPredictionService              THE single heat model (engines/heat/engine.py)
RouteEngine                        weighted Dijkstra (engines/routing/engine.py)
        │                                │
        ▼                                ▼
Providers (interfaces)             SpatialData · WeatherProvider ·
                                   CoolingSpotProvider · CrowdReportProvider ·
                                   CityBrainProvider (boundary)
```

## The heat model (one model, everywhere)

`HeatPredictionService` is the **only** heat model in the system. Both the
citizen map and the planner dashboard call it; the planner injects scenarios
through a declared `overrides` channel rather than a second formula:

```
HeatExposure (0-100) =
    base air temperature (HKO-anchored, diurnally adjusted)
  + solar_weight   · (1 - shade) · sun_strength      # sun position aware
  - shade_weight   · shade                           # building shadow geometry
  - vegetation_weight · vegetation                   # land-use fraction
  + surface_weight · paved_fraction                  # heat-retaining surfaces
  + density_weight · building_density                # urban canyon
  - wind_weight   · wind_score                       # wind x canyon suppression
  + humidity_weight · humidity_discomfort
  - water bonus
```

Key properties (master prompt sections 33, 46-48, 52):

- **HKO anchors regional conditions, geometry localises them.** Station
  temperatures are inverse-distance interpolated; they are never presented as
  street-level measurements. The UI distinguishes observed / modelled / stale.
- **Fully time-dependent.** Sun elevation/azimuth (NOAA approximation) drives
  shadow geometry per edge per hour — the same street is shaded at 09:00 and
  sun-baked at 14:00.
- **Explainable.** Every score carries signed factor contributions
  (`factors[]`) that the mobile inspector renders as ➕/➖ lines.
- **Configurable.** All weights are `HeatModelParameters` (env-overridable,
  documented prototype calibration values in `docs/configuration.md`).

### Shade model (the differentiator)

`engines/heat/shade.py` implements wall-shadow geometry: a building of height
*h* with circumradius *r* shades points that are (a) on the anti-solar side
and (b) within `r + h/tan(elevation)`. Verified by tests: morning sun shades
the west side, afternoon sun the east side; taller towers shade farther.

## Route engine

Pedestrian network → per-edge heat (time-dependent) → weighted graph →
mode-weighted Dijkstra:

```
edge_cost = alpha·duration + beta·heat·duration + gamma·slope_penalty
```

| Mode | alpha | beta | Behaviour |
|---|---|---|---|
| Fastest | 1.0 | 0.05 | Rides the direct arterial even when sun-baked |
| Balanced | 0.6 | 1.0 | Trades time against exposure |
| Coolest | 0.15 | 2.5 | Accepts long detours (green boulevards, parks) |

- Exposure is **duration-weighted** (`Σ heatᵢ·minutesᵢ / Σ minutesᵢ`): a
  30-second scorching stretch counts less than 15 minutes of moderate heat.
- Alternatives are generated by penalty re-routing when modes collapse onto
  the same streets — and accepted **only if they genuinely reduce exposure**;
  identical optimal paths are returned honestly rather than faked variety.
- The network is a deterministic mock stand-in for the **Lands Department 3D
  Pedestrian Network** (swap point: `SpatialData.network`).

## Planner simulation

`services/planner.py` maps intervention ids (`add_trees`,
`add_shaded_corridors`, `create_ventilation_corridor`, …) to the same
model-level overrides used by edge attributes, computes baseline/scenario
metrics (mean/peak heat, hot-cell share, shade, Cooling Access Gap) and a
plain-language narrative. The Northern Metropolis layer is always labelled
**CONCEPTUAL / SIMULATED** (master prompt section 5).

## Mock vs live (DATA_MODE)

`DATA_MODE=demo` (default): deterministic simulation everywhere, zero
network access — the demo cannot fail because of connectivity.
`DATA_MODE=live`: `HKOWeatherProvider` fetches HKO Open Data (`rhrread`),
caches ~10 min, and on failure serves the **last valid observation flagged
STALE**. Nothing else in the app knows which mode is active; the UI badge
communicates it (`LIVE` / `LIVE · STALE` / `DEMO · SIMULATED`).

## Extension points (do not break these)

| Seam | Interface | Replace with |
|---|---|---|
| Weather | `WeatherProvider` | HKO station feeds incl. wind/heat index/WBGT |
| Pedestrian network | `SpatialData.network` | LandsD 3D Pedestrian Network (CSDI) |
| Buildings | `SpatialData.buildings` | LandsD building footprints + heights |
| Land use / vegetation | `SpatialData.land_use` | PlanD 10 m raster, Sentinel-2 NDVI |
| Heat model | `HeatPredictionService` | Random Forest / XGBoost / GNN |
| Cooling spots | `CoolingSpotProvider` | LCSD venues open data |
| Crowd reports | `CrowdReportProvider` | Anonymised citizen submissions API |
| Smart-city platform | `CityBrainProvider` | Real City Brain integration (requirements documented in `docs/data-sources.md`) |

## Multi-agent development rules

- Feature branches touch **one** area: map/UI, heat model, routing, planner,
  data providers (see `docs/development.md` for the branch map).
- The stable contracts are `backend/app/schemas.py` ⇄
  `mobile/src/services/api/types.ts`. Changing them is an architecture change
  that must be documented and coordinated.
- Engines never import FastAPI; providers never import engines.
